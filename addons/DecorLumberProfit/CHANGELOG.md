# Changelog

История изменений аддона. Формат основан на Keep a Changelog.

## [2.2.0] - 2026-09-13

### Added

- Колонка «Рецепт» стала ссылкой: клик открывает рецепт в окне профессии
  (`C_TradeSkillUI.OpenRecipe` по `recipeID`, фолбэк `recipeSpellID`, затем
  открытие окна профессии; ховер подсвечивает название и показывает подсказку).
- Shift+клик по рецепту при открытом аукционе линкует крафтовый предмет
  в поиск АХ (`ChatEdit_InsertLink` → текст в `SearchBar.SearchBox` →
  `SendBrowseQuery`, по наличию API), чтобы сразу увидеть стоимость;
  без открытого АХ — статус-подсказка. Подсказки: `TIP_RECIPE_OPEN_HINT`,
  `TIP_RECIPE_AH_HINT`, `ST_AH_NOT_OPEN`, `ST_AH_NO_ITEM`, расширен `HINT_RECIPE`.

## [2.1.1] - 2026-09-13

### Fixed

- Цена продажи больше не «забывается»: пустой результат АХ (0 лотов) сохраняет
  последнюю известную цену (`lastPrice`, новый `Prices.MarkNoAuction`) вместо
  затирания записи; протухшая цена (старше TTL 1 ч) продолжает показываться
  в таблице, пока идёт фоновый рескан; SavedVariables читаются независимо
  от давности — стирается цена только ручным сбросом (`/dlp reset`, кнопка
  «Очистить кэш») или переустановкой. В тултипе по серверам такая цена помечена
  как stale; штамп «Цены: ...» пустыми сканами не обновляется.
- Персонаж-владелец больше не «забывается»: legacy-записи `learned=true` без
  `learnedBy` (сейвы до 2.1.0) не сбрасываются первым же false-сканом чужого
  персонажа — факт «знает хоть кто-то» переживает миграцию, пока владелец
  не запишет явное `learnedBy[имя]=true` (`Store.AnyoneKnows`).
- `GET_ITEM_INFO_RECEIVED` с `success=false` больше не удаляет сохранённый рецепт
  из базы (`ItemInfo.FailPendingForItem` сбрасывает только in-memory pending) —
  transient-ошибка сервера не стирает накопленное вместе с `learnedBy`.
- Загрузка из SavedVariables переживает ошибку API предмета (запись паркуется
  в pending вместо обрыва всей загрузки).

## [2.1.0] - 2026-09-12

### Added

- Колонка «Изучен» показывает имена персонажей, знающих рецепт (через
  запятую, по алфавиту), вместо «да/др.перс». Фолбэки «да/нет/?» оставлены
  для legacy-записей без `learnedBy`. Тот же список — в тултипе строки
  («Изучен: ...», новый ключ `TIP_LEARNED_BY`).
- Колонки «На АХ»/«Мои» помнят другие серверы (realm-scoped хранение как
  у цены): если на текущем сервере данных нет — значение с другого сервера
  со «*», расшифровка по серверам — в тултипе строки. Блок «Данные аукциона
  по серверам» теперь показывается автоматически при данных с 2+ серверов
  даже если `/dlp multirealm off` (при одном сервере — только если включён).

### Changed

- Ширина «Изучен» 55 → 110 (имена), «На АХ»/«Мои» 80 → 55 (по заголовку).
- Убрана иконка рецепта в колонке «Рецепт»: текст всегда идёт от края как
  шапка, без пустого отступа (удалён `LayoutRecipeCell`/`row._icon`; иконка
  профессии не тронута).

## [2.0.1] - 2026-09-12

### Fixed

- Иконки рецепта и профессии обрезаны через `SetTexCoord(0.08-0.92)`:
  убран «мыльный» край текстуры, из-за которого колонка выглядела со сдвигом.
  Сдвиг текста под иконку остался динамическим (только при показанной иконке).

### Changed

- Заголовки всех колонок таблицы отцентрованы (`CENTER`), было `LEFT` для
  текстовых колонок — шапка и стрелки сортировки теперь по центру ячейки.

### Added

- Вертикальные разделители 1px между видимыми колонками: в шапке (золотистые,
  в цвет подчёркивания) и в строках (серые). Перестраиваются при ресайзе
  и скрытии колонок через панель «Столбцы».

## [Unreleased]

Записи для следующего релиза добавляются в этот раздел.

### Fixed

- Рецепты с продукцией «Становится персональным при получении» (BoP, bind 1)
  и «Привязывается к отряду» (Warband, bind 8/9) не учитываются: исключены
  из скана, не пишутся в SavedVariables, чистятся из старых сейвов при
  загрузке и не попадают в очередь цен аукциона.
- Исправлено чтение bindType из `C_Item.GetItemInfo`: брался 13-й возврат
  (subclassID, у декора часто 0) вместо 14-го (bindType), из-за чего
  BoP/Warband-предметы опознавались как продаваемые и всё равно попадали
  в таблицу. Теперь bind читается через `select(14, ...)`.
- Поднят `PRICE_TTL` 900 → 3600 (1 ч; окно чтения из SavedVariables x2 = 2 ч):
  цены аукциона больше не слетают между сессиями с перерывом до 2 часов.
- BindType 3 (OnUse, «Использование: ...») считается продаваемым: белый список
  расширен 0/2 → 0/2/3. Предметы BoU продаются на АХ до использования
  (кодексы, инструменты, маунты), раньше такие рецепты молча отбрасывались
  в счётчик «непродаваемых пропущено».
- Флаг «Изучен» теперь переживает сессии. Причины потери: событие
  `NEW_RECIPE_LEARNED` с патча 9.0.1 несёт `recipeID`, а база keyed by
  `recipeSpellID` — прямая пометка промахивалась; `SerializeRecipe` терял
  `recipeID`, и мэппинг был невозможен после рестарта; поднятые из `pending`
  (холодный кэш предметов при логине) записи сохранялись со stale-флагами
  без сверки с живым API. Добавлены персист `recipeID`,
  `Store.ApplyLearnedByEvent` (мэппинг обоих неймспейсов, память + DB) и
  `RefreshLearnedFlags` для resolved-батча в `GET_ITEM_INFO_RECEIVED`.

### Added

- Столбец «Профессия» теперь иконка вместо названия (ширина 95 → 36,
  заголовок «Проф.» / «Prof.»). Клик по иконке открывает окно профессии
  (`C_TradeSkillUI.OpenTradeSkill`), но только если она изучена текущим
  персонажем — иначе клик молча ничего не делает. Имя профессии видно
  в тултипе иконки и в тултипе строки; сортировка по колонке не менялась.
  Скан сохраняет `professionID/parentProfessionID` (старые сейвы работают
  по имени, замена не требуется).
- Команда `/dlp rowheight <16-32>` — высота строк таблицы (сохранено,
  `/reload` не нужен). Шрифт строк и иконки (рецепт + профессия) масштабируются
  от высоты (20 → иконка 18px); дефолт 20 без изменений.
  Та же настройка — степпером в футере окна: `Строки: [–] 20 [+]` (шаг 2).

### Fixed

- Клик по иконке профессии не открывал окно: `OpenTradeSkill` вызывался
  с expansion-вариантом skillLine (напр. 2907), который всегда возвращает false.
  Теперь пробуются кандидаты по приоритету: `GetProfessionSkillLineID(Enum)` →
  сохранённые ID → классический ID профессии (164/165/171...) → совпавшие линии,
  запасной путь — `OpenRecipe`. Неизученная профессия — молча noop без WARN.
- Стрелки сортировки `▲▼` заменены на `^`/`v`: глифов нет в шрифте клиента,
  вместо них рисовался tofu-квадрат.
- Ширина колонки профессии 36 → 54: заголовок «Проф.» больше не режется
  до «Про...».
- Команда `/dlp multirealm on|off` — тултип по всем серверам выключен по
  умолчанию (один мир для масс), включается без `/reload`, настройка переживает
  перезагрузку (`DB.settings.multiRealm`). Сбор данных при этом идёт всегда.
- Цены, количество предметов на аукционе и собственные лоты теперь сохраняются
  отдельно по реалмам. Тултип предмета показывает сводку по всем известным
  серверам, а колонка «Мои» — сумму лотов всех персонажей аккаунта на текущем реалме.
- Добавлен сбор собственных аукционов через `C_AuctionHouse.GetOwnedAuctions()`
  и событие `OWNED_AUCTIONS_UPDATED`; снимки сохраняются по персонажам и реалмам.
- Все новые данные схемы `2` мигрируются из старого плоского `priceCache` при
  первом доступном определении текущего реалма.

- `/dlp debug skipped` — поимённый список рецептов, пропущенных последним
  сканом как непродаваемые (`имя, spellID, outputItemID, bind`), вместо
  голого счётчика. `DebugSpell` отдаёт `bindType`/`unsellable`, мета скана —
  `skippedSample`/`bindHistogram`, доступно `Core:LastSkipped()`.
- Убран лишний отступ слева в колонке «Рецепт»: текст резервировал 20px под
  иконку даже когда её нет (`rec.icon == nil`), из-за чего названия были
  сдвинуты относительно шапки и резались («Арденвельдский ф...»).
  Теперь сдвиг динамический — только при показанной иконке (`ICON_SZ + 4`),
  иначе текст идёт от края как шапка; размер иконки следует за высотой строк.
